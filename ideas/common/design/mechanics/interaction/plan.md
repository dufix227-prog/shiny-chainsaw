# Управление и взаимодействия

**Запрос автора 07.09.2026:** записать будущие взаимодействия с НПС, телефоном, инвентарём и другими системами; **P — телефон, B — инвентарь**, игрок может переназначить управление в настройках. Сейчас приоритет — запуск и тестирование имеющейся пробы; это **план, не разрешение немедленно реализовать все механики**. [Дословный журнал](../../../../requests/user-request.md).

## Подтверждённые назначения и границы

**Позднее разрешение 07.09.2026, 11:02 UTC:** реализована только [короткая проба еды в мире и инвентаря](../../../../../implementation-plan/3d-probe/inventory/plan.md). Автор подтвердил E-подбор и использование еды через B-инвентарь в этом режиме; это не разрешение всех систем основной игры.

| Действие | По умолчанию | Где и статус |
| --- | --- | --- |
| Открыть телефон | **P**, подтверждено автором | Будущая основная игра; телефона нет в прологе и текущей пробе |
| Открыть инвентарь | **B**, подтверждено автором | Уже есть для одного вида тестовой еды; будущая система — [10 базовых слотов, рюкзак, ЛКМ/ПКМ](../inventory/plan.md) |
| Переназначить управление | Настройки, подтверждено автором | Будущая система настроек; сейчас отсутствует |
| Подобрать тестовую еду | **E**, подтверждено для пробы | В режиме подбора не ест автоматически; общий ввод НПС пока не реализован |
| Подтвердить/отменить действие, закрыть окно | Не выбрано | Предложить единую схему для меню/диалога/инвентаря |

**Конфликты с лабораторией:** сейчас P — `pause_probe`, F — прямая тестовая ходьба. Без подбора E — старая еда, с подбором E — только поднять предмет. B открывает инвентарь, Enter в нём использует порцию, B/Esc закрывают окно. Не назначать P одновременно на паузу и телефон. Перед внедрением телефона перенести паузу и обновить код, подсказки, тесты и документацию вместе; **Esc для паузы — предложение**, не утверждённое новое назначение. Вспомогательные решения пробы не становятся автоматически управлением релиза.

## Черновой контракт взаимодействия — предложение

Это техническая схема без новых НПС, реплик, квестов или наград.

1. Игрок приближается к доступной цели; интерфейс явно показывает **одно выбранное действие и актуальную клавишу**, а не несколько накладывающихся подсказок. Дистанцию и правило выбора при нескольких целях уточнить в маленькой пробе.
2. Отдельное нажатие запускает доступное действие. Открытие разговора не должно тем же нажатием выбрать ответ, ударить НПС или потратить предмет. Удержание не повторяет награду/покупку/подбор каждый кадр.
3. Во время интерфейса ввод получает активное окно. Закрытие возвращает управление миру, не выполняя скрытое действие за окном. Не приравнивать каждый интерфейс к лабораторной паузе: **в прологе время в диалогах/мини-играх идёт**, как уже записано в [архитектуре](../../../../../implementation-plan/prologue/architecture.md). Расход нужд проверять отдельно по правилам соответствующей игры; эта схема их не меняет.
4. Результат применяется ровно один раз; отмена до подтверждения не списывает предметы/монеты. Прерывание, повторный вход и будущая загрузка не дублируют результат. При выбросе предмет удаляется из ячейки только после успешного создания подбираемого объекта на земле; он не может одновременно остаться в инвентаре и появиться в мире.

### НПС

Подойти → увидеть доступное действие → начать разговор → читать/выбирать → вернуться к пути либо выполнить уже согласованный переход. Новелльное окно и защита выбора описаны в [плане диалогов](../../../presentation/dialogues/plan.md). Конкретные доступные действия определяются ролью/состоянием существующего НПС; разговор не заменяет отдельные правила боя, торговли или мини-игры. Недоступность действия объяснять, не добавляя за автора причины/сюжет.

### Инвентарь

B открывает список имеющихся предметов. В пробе пока один выбранный вид еды; повторное B закрывает окно. Черновая последовательность полной системы: выбрать предмет → увидеть количество и допустимые действия → использовать/экипировать/выбросить, если это разрешено правилами предмета. Выброс переносит предмет из ячейки на землю рядом с котом, откуда его можно подобрать снова. Использование еды уменьшает запас и меняет нужды одной операцией; не оставлять предмет одновременно в мире и в инвентаре. Размер, слоты, лимиты и потеря вещей остаются в [плане механик](../plan.md), не определяются этой схемой.

### Телефон

P открывает телефон **только там, где он существует по правилам игры**. Черновая последовательность: открыть → выбрать функцию → увидеть доступность связи/адресата → подтвердить действие → получить статус. Сообщения, звонки и службы описаны [отдельно](../../../../main-story/phone/plan.md). Закрытие окна само по себе не отменяет уже принятый заказ; принятые действия и результаты должны сохраняться без дублей. Никаких настоящих звонков, доставок или обязательного реального онлайна.

## Переназначение в настройках — требования к реализации

Подтверждено наличие перебинда; следующие технические детали — предложение для его безопасной реализации:

- Хранить действия (`open_phone`, `open_inventory`, `interact`, `pause`), а не проверять буквы непосредственно в каждой игровой системе. P/B — исходные назначения, не константы поведения.
- Выбрать действие → захватить новое нажатие → показать возможный конфликт → подтвердить замену либо отменить. Во время захвата не выполнять игровое действие; не терять доступ к кнопке отмены.
- Не удалять чужое назначение молча. Дать сброс к стандартным назначениям и проверять, что необходимые действия не стали недоступны.
- Подсказки в мире, телефон, инвентарь и экран настроек должны показывать **текущее назначение**, а не жёстко написанные P/B. Проверить другую раскладку клавиатуры.
- Настройки управления хранить отдельно от сюжетного снимка: загрузка старого сейва не откатывает пользовательский перебинд. Формат настроек пока не выбран.
- Для нативного геймпада отдельно спроектировать действия и фокус меню. Эмуляция клавиатуры через Steam Input при нынешнем тесте не равна готовому перебинду внутри игры.

Проверки: P/B по умолчанию; сменить обе клавиши; старые назначения больше не срабатывают; перезапуск сохраняет выбор; конфликт/отмена/сброс; удержание не дублирует действие; инвентарь/диалог не пропускают ввод в бой или ходьбу; после закрытия управление возвращается. Проверять подсказки вместе с поведением.
