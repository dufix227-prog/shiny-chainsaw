# Контекст локальной версии

Этот файл предназначен для модели/агента, который работает с локальной версией автора вне Hoplite. Общие решения и канон читаются в [CONTEXT.md](CONTEXT.md); правила — в [AGENTS.md](AGENTS.md); игровые планы — через [ideas/README.md](ideas/README.md).

## Генерация моделей через Blender (для этой локальной модели)

Автор попросил 12.09.2026 двухшаговый процесс именно для локальной модели
(не для Hoplite — там нет GUI Blender): первый заход — сформулировать
текстовый промпт для нужного объекта (форма/масштаб/материалы/референс
стиля), второй заход — сгенерировать/собрать модель в Blender по этому
промпту и экспортировать `.glb`/`.blend`. Полное описание процесса,
референс стиля автора и список сайтов готовых ассетов — в
[implementation-plan/prologue/control/ИСТОЧНИКИ-АССЕТОВ.md](implementation-plan/prologue/control/ИСТОЧНИКИ-АССЕТОВ.md).
Готовые файлы класть в `assets/own/` и заносить в
[implementation-plan/prologue/control/РЕЕСТР-АССЕТОВ.md](implementation-plan/prologue/control/РЕЕСТР-АССЕТОВ.md)
со статусом `кандидат` до визуальной проверки автором.

## Ответственность

- Этот файл обновляет локальная модель/агент после каждого цельного проверяемого этапа.
- Hoplite не записывает сюда предполагаемое состояние локальной машины. Если автор сообщает точную ветку/коммит локальной версии, Hoplite может отметить полученный снимок как внешний факт с датой.
- Здесь хранится только техническое состояние локальной версии. Общий канон и решения не дублируются.

## Синхронизация с Hoplite

Технический контекст Hoplite находится в [game/HOPLITE_CONTEXT.md](game/HOPLITE_CONTEXT.md).

Перед переносом изменений:

1. сравнить ветки и полные SHA;
2. получить список изменённых файлов относительно общей базы;
3. если один файл менялся с обеих сторон — составить ручной план объединения;
4. не выбирать автоматически «локальная версия новее» или «Hoplite новее» для всего проекта;
5. после объединения повторить затронутые тесты и обновить оба технических контекста.

## Статусы готовности

Использовать раздельно:

- `готово кодом`;
- `проверено автоматически`;
- `визуально проверено`;
- `принято автором`.

Последний статус допустим только после явного ответа автора на конкретную показанную версию.

## Мир: дорога вместо моря — 25.09.2026

По требованию автора («сделать реальную дорогу... а не это где половина это море»)
переделан `game/3d-probe/scripts/world.gd`: море вдоль маршрута убрано, земля стала
лесной с двух сторон (земля на −70…70, трава сверху), тропа — утоптанная полоса

(`near_lake()`, канон рыбалки на 260 м), вода — озеро 180 × 900 у 260 м. Добавлена
стена леса `_tree_line()`: три ряда деревьев по обе стороны на первые 60 м маршрута,
у каждого дерева своя коллизия. Проба переименована: «У БЕРЕГА» → «ЛЕСНАЯ ДОРОГА»
(`probe.gd`, `menu_hud.gd`). Проверено: кадры `evidence/road-2026-09-25/`, регрессия
зелёная (`run` 34/0 проверяет, что берег больше не пускает в воду, `pacing` — проход
1801,5 с). **Открыто:** лес и детали стоят только на первых 60 м, дальше маршрут без
деревьев; на краю мира за боковыми деревьями видно пустоту — это следующий шаг.
