# Источники ассетов — где брать модели/текстуры

Создан 13.09.2026 по прямой просьбе автора: агент не видит, как ассет будет
смотреться в игре и не должен подбирать финальный визуал сам. Автор
просматривает сайты и присылает конкретные ссылки на понравившиеся ассеты;
агент проверяет лицензию, скачивает, интегрирует, тестирует и показывает
результат в игре.

## Правило: ассеты пачкой, финальная приёмка у автора

- Если для сцены нужен новый видимый ассет (модель, текстура, здание,
  персонаж) и одобренного варианта ещё нет, у агента два пути: создать
  ассет самому через процесс «два захода» (ниже) пачкой с другими
  нужными ассетами, либо попросить у автора ссылку с сайтов ниже.
- Ждать одобрения автора после каждого ассета **не нужно** (решение
  автора 15.09.2026): ассеты делаются пачкой, каждый заносится в реестр
  со статусом `кандидат`; автор просматривает результаты и указывает,
  что исправить или заменить. Ожидание обязательно только там, где
  вообще нельзя действовать без автора (сюжет, публикация).
- Процедурная геометрия (коробки, простые формы кодом) остаётся приемлема
  только как явно обозначенная техническая проба (см. `game/AGENTS.md`,
  раздел «Качество важнее формальной галочки»), не как замена ассету.
- Автор может сам занести ссылку на ассет в реестр (см. ниже) или просто
  прислать её в чат/файл — агент заносит и продолжает работу.

пытаться скопировать иллюстрацию впрямую.

## Процесс «два захода» для генерации моделей через Blender (локальная модель)

Автор описал 12.09.2026 двухшаговую задачу для **своей локальной модели** (не
для Hoplite — здесь нет GUI Blender и инструмента 3D-генерации):

1. **Первый заход — генерация промпта.** Локальная модель по описанию
   нужного объекта (что это, роль в сцене, масштаб относительно кота,
   референс стиля — см. ниже) формулирует текстовый промпт для
   3D-генератора/себя же в Blender: форма, пропорции, материалы, детали
   силуэта. Промпт сохраняется в план/задачу перед вторым шагом.
2. **Второй заход — генерация через Blender.** По зафиксированному
   промпту локальная модель создаёт/генерирует модель в Blender (скрипт
   Python API, встроенный генератор или ручная сборка по описанию),
   экспортирует `.glb`/`.blend` и кладёт в `assets/own/` с записью в
   [РЕЕСТР-АССЕТОВ.md](РЕЕСТР-АССЕТОВ.md) (автор, дата, статус — кандидат
   до визуальной проверки).

Правила для обоих шагов:

- Не пропускать первый заход ради экономии времени — без явного промпта
  результат сложнее сравнивать с ожиданием автора и повторять для похожих
  объектов.
- Результат второго захода — всегда `кандидат`, не финал, до показа
  автору в игре и его явного ответа (см. статусы в `game/AGENTS.md`).
- Если Hoplite получает готовый файл из этого процесса — она проверяет
  масштаб/лицензию/интеграцию, но не переделывает сам промпт или модель
  без отдельной просьбы.
- **Заход 2 — только моделью со зрением (решение автора 19.09.2026).**
  Создавать модельки в Blender может только модель, которая видит
  изображения (рендеры/скриншоты) и способна сама оценить визуальный
  результат. Модель без зрения заход 2 не выполняет — максимум заход 1
  (текстовые промпты); геометрию по её промптам создаёт vision-модель.
  Причина: первая пачка (19.09.2026) собрана моделью без зрения и автором
  не принята («то что получилось не очень»).
- **Обязательный превью-рендер при заходе 2 (проверено 19.09.2026).**
  Показывать автору объект без нормального рендера нельзя — на этом и
  потерялась первая пачка. Минимум для каждого объекта: view transform
  **Standard** (в Blender 5.x по умолчанию стоит AgX — он съедает
  насыщенность, и рыжий кот выходит бежевым, а оранжево-красная крыша
  бледно-розовой); солнце-ключ и холодный заполняющий свет; земля, на
  которую падает контактная тень (иначе силуэт не читается вовсе);
  и 3–4 ракурса на объект (для персонажа — спереди/сбоку/сзади). Готовый
  скрипт с этим ригом — `game/3d-probe/assets/own/build_pack_vision_2026-09-19.py`,
  запуск: `blender -b -P <скрипт> -- <каталог> [имя-одного-объекта]`.
  Отдельно проверять на рендере стоит то, что легко сделать «в другую
  сторону» незаметно для кода: знак наклона ската крыши, посадку мелких
  деталей (ягоды — на куст, а не рядом в воздухе), сплошные диски вместо
  колец (сплошной обод накрывает устье корзины крышкой).
