# Скачать и запустить пробу на Steam Deck

Это **нативный запуск текущих исходников на Linux x86_64**, не Web-Preview и не старый экспорт первой сцены. Проверено в Linux sandbox без графики; физический Steam Deck, его FPS и Game Mode ещё не проверены.

## Первый запуск

1. Если у тебя SteamOS, перейди в Desktop Mode. Если на Deck стоит Arch Linux и рабочий стол уже открыт — этот шаг не нужен.
2. [Скачай ZIP рабочей ветки](https://github.com/pavlodrab/solid-umbrella/archive/refs/heads/hoplite/mesambria-1d976b4b.zip) и **распакуй весь архив**. В нём в папке `game/` должны лежать `start.sh` и `3d-probe/`. Основная ветка может не содержать этих изменений. Если GitHub просит вход, используй свой обычный аккаунт; скрипту токен не нужен.
3. В распакованной папке открой терминал и выполни:

```sh
bash game/start.sh
```

Скрипт найдёт подходящий Godot 4.7.2 stable или сам скачает официальный движок, проверит SHA-512 архива и исполняемого файла, подготовит исходники и откроет игру. **Устанавливать редактор вручную, export templates, браузер, Proton или запускать `sudo` не требуется.** Для автоматической загрузки нужны `curl`, `unzip` и `sha512sum`; при отсутствии команды скрипт объяснит причину, а не будет менять систему.

Первый запуск требует сети, если подходящего движка ещё нет. Следующие запуски используют проверенный кеш и работают офлайн. Кеш: `${XDG_CACHE_HOME:-$HOME/.cache}/10000-metres-probe/godot-4.7.2-linux-x86_64/`. Повторная попытка после сбоя не использует недокачанный архив. Сама папка проекта должна быть доступна для записи импортированных файлов `.godot/`.

**Не запускай `.hoplite/browser_setup.py` на Deck:** это подготовка проверочного браузера sandbox, а не требование нативной игры. `start.sh` не выбирает лежащий в `build/` старый экспорт — запускает именно скачанные исходники.

## Как проверить

- На стартовом экране выбери «Начать пробу». Левый стик/крестовина — ходьба; удерживать F остаётся клавиатурной проверкой прямого маршрута. Без нужд от старта до 26 м примерно **01:34**, не полный пролог 500 м.
- **Y** — нужды; **A** — действие (подбор или еда); **L1** — отдых/встать; **Menu** — пауза; **R3 вне инвентаря** — новая попытка. X открывает инвентарь, B закрывает модальные окна, A подтверждает выбранную кнопку. Те же действия остаются клавишами и кнопками в окне.
- Для новой пробы включи **«Подбор: выкл»** (Y), подойди к пакету у старта и нажми **A — подобрать**. **X — инвентарь**, **A — съесть**, **B — закрыть**. Для еды включи нужды (Y) до открытия окна. В этом режиме A не ест автоматически; повтор подбора не даёт дубликатов.
- **R1** — 720p/1080p/400p, **View** — камера. Если тяжело, попробуй 400p, не меняя скорость кота.
- При уходе в другое окно включается пауза; после возвращения нажми Menu/«Продолжить».

Есть нативное управление для текущей пробы: левый стик/крестовина — ходьба; A — действие/подтвердить, а в свободном мире прыжок; B — назад/закрыть; X — инвентарь; Y — нужды; L1 или Space — сидячий отдых; L3 — полная карта; R2 удерживать — бег ×1,75 с расходом выносливости ×3; R1 — качество; View — камера; Menu — пауза; R3 — новая попытка. В начале доступны «Начать пробу», «Настройки» и «Выйти из игры»; в паузе есть возврат в главное меню и выход. Для отдыха сначала включи нужды через Y: иначе L1 не запускает лабораторный отдых и HUD это объясняет. Steam Input больше не обязателен для базовой проверки, но полноценные настройки и перебинд остаются [в плане](../../ideas/mechanics/interaction/plan.md). **B-инвентарь уже работает для тестовой еды**, а P-телефон не реализован: P всё ещё ставит пробу на паузу. Физический Deck уже дал первый отзыв, но новые L1/R2/A после исправления нужно проверить повторно.

Запиши качество, ощущения от управления, время прохода и наблюдаемый FPS. После ходьбы попробуй нужды: получается ли понять, когда поесть/отдохнуть? Не сравнивай FPS устройства с программным браузером sandbox.

## По желанию: запуск из библиотеки Steam

Сначала успешно выполни первый запуск в Desktop Mode, чтобы загрузка не мешала Game Mode.

1. В настольном Steam добавь стороннюю игру. В качестве исполняемого файла укажи **`/bin/bash`** и назови ярлык как удобно.
2. В свойствах ярлыка укажи параметры запуска — **полный путь к распакованному `game/start.sh` в кавычках**, затем `--fullscreen`. Например, заменив путь на свой:

```text
"/home/deck/Downloads/solid-umbrella/game/start.sh" --fullscreen
```

3. Поле рабочей папки («Start In») — распакованная папка репозитория. Лаунчер не зависит от неё, но правильный путь упрощает диагностику. **Принудительную совместимость Proton не включать:** здесь Linux-движок.
4. Оставь Steam Input на стандартной раскладке контроллера: у пробы есть нативные действия Deck, поэтому эмуляция WASD и мыши не нужна для основного теста. Трекпад можно оставить как указатель для мышиного резервного пути. Конкретная раскладка на физическом устройстве ещё не проверена.

Скрипт не создаёт ярлык и не меняет настройки Steam или контроллера без тебя. Перенёс распакованную папку — исправь путь в ярлыке. Это не статус Steam Deck Verified.

## Если не запустилось

Запускай из терминала, чтобы увидеть ошибку, и сохрани её текст. Полезные команды:

```sh
bash game/start.sh --help
bash game/start.sh --setup-only
bash game/start.sh --headless --quit-after 60
```

Последняя команда проверяет импорт и запуск логики **без окна** — она не проверяет графический драйвер. Если движок уже установлен отдельно, можно указать исполняемый файл точной версии:

```sh
GODOT_BIN="/полный/путь/Godot_v4.7.2-stable_linux.x86_64" bash game/start.sh
```

Скрипт не переключает версию движка проекта, не отключает защиту файловой системы SteamOS и не устанавливает системные библиотеки. Ошибку драйвера или отсутствующей библиотеки нужно разбирать по её тексту, а не лечить запуском от root.

Проверка лаунчера: 15 автоматических сценариев; отдельно настоящая первая загрузка движка в чистый кеш, импорт свежей копии исходников и повторный headless-запуск с заблокированной загрузкой. Пути с пробелами поддерживаются. Это не заменяет запуск с графикой на устройстве автора.
