# Гайд: как делать графику «как в меню»

Для любой модели, которая продолжает работу. Стиль утверждён автором 25.09.2026 по пробе `game/3d-probe/scenes/style_probe/` («то что я увидел это просто разьеб»). Образец — картинка меню `game/3d-probe/assets/art/menu_background_candidate.jpg` и кадры `game/3d-probe/evidence/style-probe-2026-09-25/`.

Сначала открой кадры пробы и картинку меню. Всё, что ты делаешь, сравнивай с ними, а не со своим представлением о «вокселях».

## 1. Из чего складывается вид

Вид складывается из пяти вещей. Если хоть одна пропала, получается «слишком квадратно и пиксельно» — автор это уже отверг.

1. **Мелкие кубики, не крупные блоки.** Размер вокселя 0,1–0,35 единицы: трава и цветы — 0,1, берёза и куст — 0,25, ель и камень — 0,3, лиственное дерево — 0,35. Кот ≈ 3,4 единицы ростом, так что дерево — это сотни кубиков, а не десяток блоков.
2. **У каждого кубика свой оттенок.** Никаких текстур: цвет хранится в вершинах (`vertex_color_use_as_albedo`). Цвет берётся из палитры 4–8 близких цветов от тёмного к светлому: верх кроны светлее, низ темнее, плюс случайный разброс (`Recipes._pick`). Одноцветный кубик = «проба», пёстрая мозаика = стиль.
3. **Рваные живые формы.** Кроны — эллипсоиды с шумом по краю (`_blob`), ели — ярусы-конусы (`_disc`), не кубы и не ровные шары.
4. **Свет заката.** Низкое тёплое солнце сбоку, ACES-тонмаппинг, SSAO, лёгкое свечение, мягкий розово-оранжевый туман, у листвы подсветка на просвет (`backlight` в `materials/foliage.tres`). Всё настроено в `style_probe.tscn` → `WorldEnvironment` и `Sun`.
5. **Глубина.** Далеко видно долину с рекой, горы, облака и дальний лес. Даль делается крупными кубиками (1,5–6 единиц) и `MultiMesh`, без коллизий.

| Файл | Что там |

| `scenes/style_probe/kinds/*.tscn` | Готовые объекты: меш и коллизия. Их можно открыть в редакторе. |

## 3. Как добавить новый объект (пример: пень)

1. **Рецепт** в `voxel_recipes.gd`. Скопируй похожий рецепт и поменяй форму (в файлах проекта отступы — табами, в примере ниже пробелы только для Markdown):

   ```gdscript
   ## Пень: короткий толстый ствол со светлым срезом сверху.
   static func stump(seed: int) -> ArrayMesh:
       var rng := _rng(seed)
       var wood := Mesher.new(Vector3.ONE * 0.3)
       _trunk(wood, rng, 4, 0, 3, BARK)
       for x in range(-2, 2):
           for z in range(-2, 2):
               wood.set_cell(Vector3i(x, 3, z), Color("#b08a5a"))
       return _finish([[wood, VOXEL]])
   ```

   Правила для рецепта: палитра из 4–8 оттенков, а не один цвет; `seed` задаёт одинаковый результат при каждой сборке; листва идёт в материал `FOLIAGE`, всё остальное — в `VOXEL`.
2. **Вид** в `style_probe_builder.gd` → `_build_kinds()`. Задай коллизию по видимой форме:

   ```gdscript
   var stump_shape := CylinderShape3D.new()
   stump_shape.radius = 0.6
   stump_shape.height = 1.0
   _save_kind("stump", Recipes.stump(15), stump_shape, Transform3D(Basis(), Vector3(0, 0.5, 0)))
   ```

   Проходимое (трава, цветы) — без коллизии, через `MultiMesh`, как `_scatter_ground_cover`. Замедляющее — как `_save_bush` (`Area3D` + `bush.gd`).
3. **Расстановка** — функция в сборщике по образцу `_plant_path_edges`. Перед установкой вызывай `_claim(x, z, радиус)`, иначе объекты встанут друг в друга.
4. **Пересобрать, проверить, снять кадр** (раздел 5).

## 4. Размеры и правила мира

- Кот ≈ 3,4 единицы ростом (модель ×1,35 в `scenes/player/cat_player.tscn`), капсула радиусом 0,55. Прыгает примерно на 1,3 единицы.
- Тропа шириной 6,7–10,3 единицы (решение автора «тропа пошире»), плавно петляет и меняет ширину.
- У каждого дерева своя коллизия ствола. **Невидимых стен нет:** граница — это забор, обрыв, подъём, завал. Всё твёрдое должно быть видно (тест это проверяет).
- **Камера не проходит сквозь объекты.** Кроны и кусты для кота проходимы, а для камеры — нет: у каждого дерева и куста есть дочернее тело `CameraBlocker` на слое 3 `camera_only` (выпуклые оболочки поверхностей меша, делает `_add_camera_blocker`). `SpringArm3D` кота видит слои 1 и 3 (`collision_mask = 5`), кот — только слой 1. Новому объекту, в который может упереться камера, нужен такой же блокер. Когда камеру прижимает ближе 3 единиц, кот плавно становится прозрачным (`cat_player.gd`, `FADE_*`).
- Большие кроны не ставить у самой тропы (не ближе 4,5 от края), а лес за стартом начинать подальше: камера за котом не должна оказываться в листве.
- У широких крон (лиственные) нижний край — выше камеры (около 9 единиц), у елей крона начинается не ниже ~3 единиц: иначе камера оказывается под кроной и видны «плиты» ярусов.
- Темп маршрута: 12,24 единицы на метр пути.

## 4а. Новая игровая сцена — что подключить

Каждая сцена, где игрок ходит, должна иметь узлы `CatPlayer`, `HUD`, `Pixelate`, `PauseMenu` (как в `style_probe.tscn`) и в `_ready()` вызывать:

```gdscript
GameSettings.apply_to_world(self)   # настройки графики: тени, туман, SSAO, дальность, угол обзора
SaveGame.restore_into(self)         # положение кота после загрузки снимка
```

Без этого настройки графики не применятся, а загрузка поставит кота в начало.

## 5. Команды

```bash
G=~/.cache/10000-metres-probe/godot-4.7.2-linux-x86_64/godot    # движок ставит bash game/start.sh --setup-only
cd game/3d-probe

# Пересобрать. ОБЯЗАТЕЛЬНО с окном (xvfb-run на сервере), не --headless:
# в headless Godot не хранит данные MultiMesh, и трава с дальним лесом сохранятся пустыми.
xvfb-run -a $G --path . -s res://tools/build_style_probe.gd

# Проверки
$G --headless --fixed-fps 60 --path . -s res://tests/style_probe.gd

# Кадр: сцена, файл, метры от старта, поворот камеры (°), наклон (°)
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a -s "-screen 0 1280x800x24" \
  $G --path . --resolution 1280x800 -s res://tools/capture.gd -- \
  res://scenes/style_probe/style_probe.tscn evidence/<папка>/кадр.jpg 0 10 -12
```

В редакторе Godot: открыть сцену → выбрать узел `Builder` → «Пересобрать пробу» в инспекторе → Ctrl+S.

## 6. Ошибки, на которых уже обжигались

| Что видно | Причина | Как исправить |
|---|---|---|
| Земля или объект не рисуются, кот проваливается | Перевёрнут порядок вершин треугольника | Лицевая сторона — обход по часовой; в `voxel_mesher.gd` порядок уже проверяется по нормали, копируй оттуда. |
| Трава и дальний лес пропали после пересборки | Сборка шла с `--headless` | Пересобрать с окном (`xvfb-run`). |
| Всё залито розовой дымкой, горы — сплошная стена | Туман слишком густой | `fog_density` не больше ~0,001, объёмный туман выключен. |
| Картинка серая и плоская | Слишком сильный рассеянный свет | `ambient_light_energy` ≈ 0,75, солнце ≈ 2,6 и сбоку. |
| Камера «ныряет» в листву | Нет `CameraBlocker` у объекта или у `SpringArm3D` маска без слоя 3 | См. раздел 4; кадр — `tools/capture_camera_block.gd`. |
| Камера упёрлась, экран закрыт головой кота | Не работает прозрачность кота | Проверить `_process` в `cat_player.gd`. |
| «Слишком квадратно и пиксельно» | Крупные блоки, одноцветные кубики, пиксельные текстуры | Мелкие воксели и палитра оттенков (раздел 1). |
| Тест проходит, а автору не нравится | Проверялась только логика | Всегда снимать кадр и сравнивать с картинкой меню. |

## 7. Перед тем как сказать «готово»

- [ ] Работа сделана маленьким куском, не на весь участок сразу (правило автора).
- [ ] Новый объект сделан из мелких вокселей с палитрой, форма рваная.
- [ ] У твёрдого объекта коллизия по видимой форме; проходимое — без коллизии.
- [ ] Пересобрано с окном; `tests/style_probe.gd` проходит.
- [ ] Снят свежий кадр, лежит в `evidence/`, сравнён с картинкой меню.
- [ ] В ответе автору — кадр и честный статус: `готово кодом` / `проверено автоматически` / `визуально проверено`. «Принято автором» — только после его ответа.
- [ ] Сюжет, имена, реплики не придуманы — это решает автор.
